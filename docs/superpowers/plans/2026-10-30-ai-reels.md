# AI reels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Rev 2 (after adversarial review: 18 findings, all addressed below).

**Goal:** Make mobile page 02 (R01–R13) produce real AI reels: plan → Higgsfield render → self-approve by sending → Instagram or download.

**Architecture:** A studio reel is a `ContentItem` (`INSTAGRAM_REEL`, `studio = true`) whose version body carries the plan; agents that write posts ignore studio items. A `ReelRender` row per render attempt drives a step machine (voice → clips → stitch → store) through the job queue; every Higgsfield call happens outside any DB transaction, between a "claim" write and a "save ids" write. Approval, quality, credits and Instagram publishing reuse existing services with additive changes.

**Tech Stack:** Next.js 15 route handlers, Prisma/Postgres (Neon), vitest, Higgsfield REST, Expo (expo-router) + new `expo-video`, `expo-file-system`, `expo-sharing`.

**Spec:** `docs/superpowers/specs/2026-10-30-ai-reels-design.md`

## Global Constraints

- Screens stay as built; additions only: R06 "Downloaded · Posted it? Add link" line + one-field sheet, and R07 "Not right? Ask for changes" link → R04 (pending owner OK).
- Price is computed on the server: `Σ clipSeconds(speechSeconds(scene.voiceText)) × 2` credits. Scene `seconds` is derived, never client-set. Charged once per render attempt with `refId = ${versionId}:${attempt}`; refund on failure; "Try again" = new attempt = new charge (the failed one was refunded); redo = new version = new charge.
- Starter grant stays 20. `InsufficientCreditsError` → API 402 `{ needsPlan: true }` → app opens `/plans/reels`.
- `ReelPlan.scenes` 2–6 (the existing reel rule needs ≥ 2 script lines). Scene voice ≤ 30 words (≈ 15 s).
- Kling 3.0 Standard image-to-video `POST /kling-video/v3.0/std/image-to-video`, `sound: "off"`; fall back to Kling 2.6 Pro if Task 0 shows no 9:16.
- Higgsfield auth `Authorization: Key ${HIGGSFIELD_API_KEY_ID}:${HIGGSFIELD_API_KEY_SECRET}`, base `https://api.higgsfield.ai`; keys only in `apps/web/.env`, entered by the owner.
- No HTTP call to Higgsfield inside `prisma.$transaction`.
- Webhook = nudge only: re-fetch status with our key; download only from URLs passing `isHiggsfieldResultUrl`.
- Every `photoKey` must start with `${workspaceId}/${brandId}/` and match the media file-name pattern (as `publishing.ts:212-213`).
- Scheduled/published reels carry `videoKey` (not a URL) in the attempt target; signed at posting time. Client `videoUrl` is rejected for studio reels.
- While a render is running, plan edits and chat on that item return 409.
- Self-approval allowed for studio reels only.
- New strings English only. Commit messages: change + why, no trailers, never mention tests.
- Prisma commands run from `apps/web` (`npx prisma …`), not with `-w`.

## Review Focus

1. Webhook + poll + self-tick at once → one submit per step (Task 5 `claim is single-flight`).
2. Crash after Higgsfield accepted but before ids saved → never blind resubmit; stale claim → FAILED + refund + logged for a person (Task 5 `stale claim fails, never resubmits`).
3. Caption edit after render keeps `scenes`/`videoKey` and re-runs Quality for that item (Tasks 2, 6).
4. "Try again" after a refunded failure charges again; a double tap charges once (Task 2, Task 5).
5. Foreign `photoKey`, non-Instagram post link, link while SCHEDULED → rejected (Tasks 3, 6).

### Task 5: Render engine

**Files:** create `server/reels/render.ts`; register in `server/jobs/runner.ts`. Test: `tests/reel-render.test.ts`.

**Consumes:** Tasks 2–4; `putMedia`, `mediaKey`, `signedMediaUrl`, `enqueueJob`, `startAgentRun`, `lock`/`TX` from publishing.

**Produces:**
- `REEL_RENDER_JOB = "reel.render"`.
- `startRender({ workspaceId, brandId, userId, itemId, version }): Promise<ReelRender>` — under `lock(item)`: version must be latest, `isStudioPlan`, `planProblems` empty, no render of this item in VOICE/CLIPS/STITCH/STORE (409). `attempt = 1 + max attempt for this version`; `spendCredits({ amount: reelPrice, reason: "reel-render", refId: \`${versionId}:${attempt}\` })`; create row (32-byte `webhookSecret`); `enqueueTick(render)`.
- `enqueueTick(render)` — `enqueueJob({ type: REEL_RENDER_JOB, payload: { renderId }, idempotencyKey: \`reel:${id}:tick:${render.ticks}\`, runAt })`, after incrementing `ticks` (so keys never repeat).
- `nextStep(render, statuses): { action: "submit" } | { action: "wait" } | { action: "advance"; to: ReelRenderStep; outputs } | { action: "store"; url } | { action: "fail"; error } | { action: "done" }` — pure. Rules: no ids for current step and `claimedAt` null → submit; `claimedAt` set, no ids, older than 10 min → fail ("Submit outcome unknown"); ids present: any failed → fail; all completed → advance (VOICE→CLIPS→STITCH→STORE); else wait.
- `advanceRender({ renderId })` — load row; fetch statuses for current ids (no transaction); act:
  - **submit:** `updateMany({ where: { id, step, claimedAt: null }, data: { claimedAt: now } })`; `count !== 1` → return. HTTP submits (no transaction). Then `update({ requests[step] = ids, claimedAt: null })`. VOICE: one TTS per scene. CLIPS: download each voice, `wavSeconds` → `voiceSeconds`; `animate(signedMediaUrl(photoKey, 6h), direction(+redo note), clipSeconds(voiceSeconds[i]))`. STITCH: ordered pairs.
  - **advance:** `updateMany({ where: { id, step: from }, data: { step: to, outputs } })`.
  - **store:** `fetchResult(url)` → `putMedia(mediaKey(scope, uuid.mp4), "video/mp4")` → under `lock(item)` + `TX`: new version = rendered version body + `videoKey`, `createdBy: "agent"`; item `DRAFT_REVIEW`; render `DONE`, `videoKey`. Then `startAgentRun({ agentKey: "quality", trigger: "event", input: { itemId } })`.
  - **fail:** step FAILED, `error`, `refundCharge(ws, chargeId)`, AuditEvent `reel.render.failed` (so a person sees stale-claim losses).
  - not done → `enqueueTick` with `runAt` +20 s. Give up only on Higgsfield `failed` or 24 h since `createdAt`.
- `failRender(payload, error, exhausted)` — job `onFailure`: if `exhausted`, fail as above.
- `renderView(itemId)` — latest render per version: `{ step, error, attempt, price, videoKey }`.

- [ ] **Step 1: Failing tests:** `nextStep` table (incl. empty `requests` at VOICE → submit, not advance); `claim is single-flight` (`updateMany` count 0 → no `speak`); `stale claim fails, never resubmits`; `resume polls stored ids` (ids present, queued → no submit, tick enqueued with new key); `startRender twice` → one charge (same refId); `try again charges a new attempt`; `failure refunds`; `store refuses foreign urls`; `store starts quality for the item` (`startAgentRun` input `{ itemId }`); `edits blocked while rendering` (startRender/plan save 409 when a render is in CLIPS).
- [ ] **Step 2–4:** FAIL → implement; add `[REEL_RENDER_JOB]: { run: advanceRender, onFailure: failRender }` → `npm test -w web` all pass.
- [ ] **Step 5:** Commit: "Render reels through Higgsfield one step at a time, without double submits, refunding failed renders"

Publish now/schedule = existing content `decide` (skipped by the app when approval holds) + `publish` (studio → `videoKey` path from Task 2).
- `GET …/reels/:id` (`brand.read`) → `{ item, plan, price, render, checks, approval, accounts, chat }`; calls `kickIfDue()`; if the render is unfinished and `updatedAt` > 60 s ago, `enqueueTick`.
- `POST /api/v1/webhooks/higgsfield/:renderId?s=` → `hitRateLimit`; `timingSafeEqual` vs `webhookSecret`; on match `enqueueTick` + `kickRunner()`; always `200 {}`.
